# Источники и границы обоснования

Проверено при подготовке пакета: **11 октября 2026 года**. Ссылки на изменяемую
документацию не заменяют повторную проверку конкретной установленной версии.

Это прикладной авторский протокол ревью, составленный под запрос пользователя.
Каталог паттернов, классификация DEFECT/GAP/DECISION/TRADEOFF/EDITORIAL, лимит вопросов,
эвристика остановки поиска и фильтр спайков — проектные правила этого skill, а не
официальный стандарт NASA, NIST, OpenAI или OpenCode. Их эффективность на конкретных
моделях не измерялась. Сценарии в evals — заготовки для проверки поведения.

## S1. Agent Skills — Specification

Источник: `https://agentskills.io/specification`

Использовано для формата: директория skill, SKILL.md с name/description,
необязательные references/assets, относительные ссылки и загрузка материалов по
необходимости. Основное описание компактно; дополнительные детали вынесены отдельно.
Стандарт формата не гарантирует одинаковое обнаружение и поведение во всех агентах.

## S2. OpenAI — Build skills / Codex

Проверенный вход: `https://developers.openai.com/codex/skills`
Текущая страница после перенаправления: `https://learn.chatgpt.com/docs/build-skills`

Разделы: How ChatGPT and Codex use skills; Where Codex loads local skills; Best practices.
Использовано для путей `.agents/skills`, пользовательской установки и явного упоминания
через `$`. В пакете нет зависимости от OpenAI API или обязательного плагина.

## S3. OpenCode — Agent Skills

Источник: `https://opencode.ai/docs/skills/`
Разделы: Place files; Understand discovery; Write frontmatter; Recognize tool description.

Подтверждены общие пути `.agents/skills` и собственные пути OpenCode, а также загрузка
через native skill tool. Пакет не требует OpenCode-специфичных ключей, slash-команд
или provider-конфигурации. Поддержка путей проверена по документации, не запуском
на машине пользователя.

## S4. NASA — Appendix C: How to Write a Good Requirement

Источник: `https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/`
Разделы: C.3; C.4 Clarity, Consistency, Traceability, Verifiability/Testability.

Ориентир для ясности, необходимости, согласованности и проверяемости требований.
Рекомендация описывать требуемое поведение положительно соответствует запросу
пользователя. Skill не переносит формализм аэрокосмических проектов в небольшой
репозиторий и отдельно сохраняет полезные запреты и ограничения.

## S5. OpenAPI Initiative — OpenAPI Specification

Индекс актуальной редакции: `https://spec.openapis.org/oas/latest.html`
При просмотре страница имела заголовок OpenAPI Specification v3.2.1.
Разделы: OpenAPI Object; Operation Object; Parameter Object; Response Object;
Security Requirement Object; Security Considerations.

Использовано для предметов сопоставления схемы: операции, параметры, ответы,
ссылки на компоненты и правила доступа. Нельзя требовать перехода проекта на эту
редакцию: при ревью применяются реальная версия его API и соответствующий диалект OAS.
Схема не подменяет все внешние поведенческие ограничения сервиса.

## S6. NIST AI 600-1 — Generative Artificial Intelligence Profile

Источник: `https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf`
Дата публикации: июль 2024 года.
Проверенные места: §2.2 Confabulation, печатная страница 6 (10-я страница PDF);
MS-2.5-003, печатная страница 31 (35-я страница PDF).

Профиль описывает уверенно предъявляемые ошибки, противоречия и вымышленные
обоснования/ссылки, а также рекомендует проверять источники и цитаты сгенерированного
содержимого. Это основание для требования доказательств, а не статистика частоты
лишних спайков и не сертификация данного skill.

## S7. Anthropic — Effective context engineering for AI agents

Источник: `https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents`
Разделы: The anatomy of effective context; Context retrieval and agentic search;
Context engineering for long-horizon tasks.

Использовано как ориентир для адресного извлечения нужной информации и сохранения
существенных решений без раздувания контекста. Минимальность не означает утрату
ограничений. Четыре подагента в этом skill — выбранный пользователем способ ревью,
а не требование статьи; новый оркестратор или сервис для него не требуется.

## S8. Anthropic — Best practices for Claude Code

Источник: `https://code.claude.com/docs/en/best-practices`
Разделы о проверяемых результатах, самостоятельных спецификациях и ограничении
бесконечного исследования.

Ориентир для различения заявления «готово» и предъявленного основания готовности.
Skill не заимствует циклы реализации, обязательный запуск кода или правила записи:
его задача заканчивается ревью и обсуждением решений.

## Как использовать источники

При сопровождении skill проверяй применимость конкретных правил, а не просто наличие
ссылки на авторитетный сайт. При ревью проекта важнее источники именно его требований,
контрактов и ограничений. Не загружай весь этот список при каждом запуске и не
копируй длинные первоисточники в репозиторий пользователя.
