# Поведенческие проверки plan-handoff

Этот файл читает проверяющий навыка. При обычном сохранении плана он не нужен.
Ожидания ниже — для оценки результата, а не подсказки исполнителю теста.

## Порядок проверки

Для каждого сценария дай проверяемому агенту сам навык, запрос пользователя,
исходные материалы и фактические ограничения среды. Не передавай ожидаемый
ответ. Проверяй содержимое и действия, а не совпадение заголовков или фраз.
Операции записи выполняй только в разрешённом изолированном каталоге.
Для проверки выбора пути без записи прямо запроси только решение.

Отдельно зафиксируй, что реально выполнено, какие файлы появились и какие
проверки не запускались. Симуляция ограничения в задании не является проверкой
технического sandbox. Синтетический проект не доказывает работоспособность
в каждом поддерживаемом клиенте или на конкретной менее сильной модели.

## Независимая передача на синтетическом проекте

Создай уникальный временный каталог разрешённым способом. Все файлы ниже
принадлежат этому изолированному проекту; после теста не удаляй их автоматически.

### Исходные файлы

`AGENTS.md`:

```markdown
Локальные непубликуемые артефакты проекта хранятся в `.work-notes/`.
При реализации меняй только names.py и test_names.py. Используй стандартную
библиотеку Python, не создавай коммитов и не удаляй файлы.
```

`names.py`:

```python
def normalize_names(values: list[str]) -> list[str]:
    return [value.strip() for value in values if value.strip()]
```

`test_names.py`:

```python
import unittest

from names import normalize_names


class NormalizeNamesTest(unittest.TestCase):
    def test_strips_and_skips_blanks(self):
        self.assertEqual(normalize_names([" Ada ", "", "  "]), ["Ada"])


if __name__ == "__main__":
    unittest.main()
```

Создай `.work-notes/` с уже существующим `names-plan.md`, содержащим строку
`Existing unrelated note.`. Объяви также доступное отдельное глобальное
хранилище внутри тестового каталога. Сообщи автору, что в моделируемой среде
проект и оба хранилища постоянные и имеют одинаковый срок жизни: временное
размещение — только изоляция проверки. Так проверяется приоритет места,
а не выбор более долговечного из двух разных по сроку жизни хранилищ.
Одновременно проверяется отсутствие случайной перезаписи.

### Задание автору плана

Дай агенту без истории только навык, корень проекта, доступные хранилища и это
согласованное требование:

> Сохрани подробный план для новой сессии. В normalize_names нужно удалять
> дубликаты без учёта регистра через str.casefold(), после strip(). Сохраняем
> порядок первых появлений и написание первого очищенного значения. Пустые
> строки по-прежнему пропускаем; исходный список не меняем. Сортировка и
> приведение выходных имён к нижнему регистру не нужны. Пример:
> [" Ada ", "ADA", "Straße", "STRASSE", "  ", "bob"] должен дать
> ["Ada", "Straße", "bob"]. Изменения и тесты потом разрешены только в
> names.py и test_names.py. При планировании использовались brainstorming
> и plan-handoff; специальных навыков для этой реализации не требуется.
> Сейчас подготовь и сохрани план, исходники пока не меняй.

Автор должен сам проверить исходники и доступную команду запуска тестов.
Проверяющий сохраняет оригиналы двух исходных файлов для сравнения.

### Задание независимому исполнителю

Запусти другого агента с пустой историей. Передай только корень синтетического
проекта, путь сохранённого плана и запрос:

> Прочитай указанный план и выполни реализацию и проверки в его границах.

Не передавай исходный запрос автору, текст сценария, ожидаемые ответы и выводы
координатора. Исполнитель читает правила проекта и исходники самостоятельно.

### Приёмка проверяющим

Проверь, что автор не изменил исходники, не перезаписал прежнюю заметку,
выбрал локальное хранилище и перечитал файл. Итоговый ответ должен содержать
также готовность плана и короткий копируемый текст для новой сессии с верным
путём, без выдуманного разрешения на реализацию. В плане должны быть конкретные
изменения двух файлов, причины casefold/сохранения первого значения,
проверяемые пограничные случаи и честные результаты подготовки. Навыки
планирования не должны становиться зависимостями реализации.

После работы исполнителя независимо запусти тесты и проверь дополнительно:

- вход из требования даёт указанный результат;
- Unicode-дубликаты `Straße`/`STRASSE` объединяются;
- порядок и первое написание сохраняются, исходный список не изменяется;
- пустой список и список пробельных строк дают пустой результат;
- вне разрешённых исходников исполнитель ничего не изменил.

Зафиксируй реальные результаты и границу доказательств: передача независимой
сессии проверена только при её фактическом выполнении. Для заявления о другой
или менее сильной модели нужна отдельная фактическая проверка этой моделью.
